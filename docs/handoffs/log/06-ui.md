# 06 — UI (done 2026-10-07)

## What was built

- `ui/wm.js` (159 lines): MDI windows on `#desktop`, drag by title bar (pointer events), CSS resize, minimize to a taskbar button, focus/z-order, clamped to the desktop, `persist` windows (Board, Brain, Inbox, Settings) keep position and size in `localStorage`. Also `dialog()` (native `<dialog>`, resolves with the button label) and `menu()` (pop-up with submenus, used by Start and the card menu). `open(..., { background })` opens behind the focused window.
- `ui/app.js`: data layer (REST + `/events`) and every window. Board (four columns, toolbar Launch / Launch all / New brainstorm / New ticket / Housekeeping, status bar, cards with model/effort/cli badges, defaults in grey italic, running / needs human / waits on / retry / merged badges, right-click menu with Model, Effort and CLI submenus, Retry merge, Reset, Delete, pointer drag limited to operator moves). Ticket (tabs: Ticket form, Notes timeline, Runs with each run's rendered prompt and stored output, Diff, live Grants with Revoke, Audit). Terminal (xterm.js on `/pty/<key>`, fit addon, resize, mic in the title bar). Brain (search, add note). Inbox (open questions, answer field). Settings (Models table per CLI × phase, CLI paths, Claude trust status and Clear, Grants with Revoke, Voice: model status / Download, backend selector with only `local`, push vs toggle; General: sounds). Taskbar with Start menu, Inbox count, running-agent count, clock. Keys: Esc, Ctrl+L, Ctrl+N.
- `ui/voice.js`: `micButton(onText)` with idle / recording / transcribing / error states, `micEverywhere()` (MutationObserver gives every text field a mic; `data-mic="off"` opts out; xterm's helper textarea excluded), `transcribe(blob)` with a `backends` table (only `local`), the download dialog and progress, the microphone-denied dialog.
- `ui/index.html`, `ui/app.css`; vendored `ui/vendor/xterm/` (xterm 6.0.0, addon-fit 0.11.0) and `ui/vendor/transformers/` (transformers.js 4.3.0, onnxruntime-web 1.31.0-dev asyncify runtime, 27 MB wasm). Versions chosen at least two weeks old.
- Daemon:
  - `settings.ts`: `CLIS`, `EFFORT` (moved here from launcher/mcp so the zod schemas load without an import cycle), zod schemas for `models.json` and `settings.json`, `readConfig` / `writeConfig` (temp file + rename), `runSettings` (moved from lifecycle; adds the `plan` phase for brainstorms and the CLI `path`).
  - `voice.ts` + `daemon/voice-model.json`: pinned `onnx-community/whisper-base.en` revision, 7 files with size and SHA-256; `status`, `download` (size cap, hash check, deletes on mismatch, shared in-flight promise, progress counter), `voiceFile` (manifest-listed paths only).
  - `launcher.ts`: `spawnSession` shared by `launch` and the new `launchBrainstorm`; `Session` gains `key`, `phase`, `model`, nullable `runId` / `ticketId`; optional executable `path`.
  - `lifecycle.ts`: `changed(ticket)` emits `{ticket}` on `events` `'change'` after every `apply` and every session exit; `housekeeping(b, body)` and `brainstorm(b)` exported.
  - `api.ts`: `/api/tickets/housekeeping`, `/tickets/:id/diff`, `/inbox`, `POST /brain`, `/sessions`, `/brainstorm`, `/config/(models|settings)`, `/trust`, `/voice`, `/voice/download`; every successful mutation emits a change event; handlers may be async.
  - `mcp.ts`: every `ok` tool call emits a change event for its ticket.
  - `server.ts`: `/events` forwards sound and change frames; `/pty/-<n>` accepted (brainstorm); `/voice-model/*`; `.mjs` / `.wasm` MIME; CSP extended (below). `git.ts`: `ticketDiff`. `trust.ts`: `trustStatus`, `untrustClaude`, shared `save`.
- Tests: `voice.test.ts` (6: status touches no network, good download kept, wrong hash rejected and deleted with both hashes named, oversize response cut off, tampered file replaced, only manifest paths served). `ui.test.ts` (5, headless Edge/Chrome through `test/cdp.ts`, a dependency-free DevTools client on Node's WebSocket): illegal drop snaps back with the exact status-bar message and a legal drop moves the card without a reload; Inbox answer clears the card's needs-human badge (fake agent asks, gets the answer, commits it, ticket merges); window position survives reload; first mic press shows the download dialog and Cancel fetches nothing; the bundled WAV transcribes to "add a test for the merge queue" with the hash-verified model. `lifecycle.test.ts` asserts change frames alongside the ding; `launcher.test.ts` Codex argv; `server.test.ts` CSP. Suite: 122 tests, ~26 s (first run also downloads the model, ~80 MB).
- Docs: new `docs/OPERATOR.md` with screenshots in `docs/img/`; `ARCHITECTURE.md` (REST rows, Events, UI, Voice, brainstorm, repo map, CSP), `SECURITY.md` (CSP, Voice model, operator files, session dir rule, brainstorm, mic prompt), `DATA.md` (settings files, model dir, audit tools), `LIFECYCLE.md` (plan phase, paths, change frames), `CLIS.md` (Codex MCP approval, live brainstorm check, Settings trust clear), `README.md`.

## Acceptance, as checked

Scripted in headless Edge (fake mic playing the WAV, fake agent CLI), all PASS:
1. Ctrl+N brainstorm → two tickets appear → Ctrl+L → five terminals open by themselves → both tickets reach Done and merge → two dings; `window.__noReload` survived.
2. Illegal drop → `#5 cannot be dragged from Backlog to Done. Allowed: In Progress.`, card stays.
3. Settings → Grants → Revoke → terminal marked ended in ~150 ms.
4. 1280×720: `scrollWidth` 1280, no horizontal scroll (also in WebView2).
5. Push-to-talk in the Inbox answer field and in a terminal title bar both produced the sentence; the terminal got it without Enter. Every one of 182 requests went to `127.0.0.1` (resource timing), which is what "network disabled" requires.
6. Covered by `ui.test.ts`.

**WebGPU/WASM in Tauri's WebView2 (Windows 11, WebView2 154):** `navigator.gpu.requestAdapter()` returns an adapter; transcription runs on **webgpu**: fixture correct, 7.0 s first call (load included), 2.9 s warm. Headless Edge has no adapter and falls back to WASM (correct, ~9 s first call). Probed with `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=…` on the real shell.

**Live Codex brainstorm** (Codex 0.154.0, `gpt-5.6-luna`, scratch repo, real home with a temporary `~/.kanban95` removed afterwards): first attempt failed twice over, see Deviations; after the fixes the planner read its brief, called `list_tickets`, `brain_search`, `create_ticket` (ticket created), wrote nothing.

## Deviations from the handoff

- **Codex planner fixes, outside the UI files.** (a) `-c mcp_servers.kanban95.default_tools_approval_mode=approve` on every Codex launch: under `-a never` Codex refused every board tool ("MCP tool call requires approval, but approval policy is never"); `auto` did not help, `approve` did. (b) A Codex session dir is no longer owner-only: the read-only sandbox runs as another Windows account and got "access-denied" on `prompt.md`. Codex's token never touches that dir (env var), so only Claude's dir, which holds `mcp.json`, stays owner-only.
- **Brainstorm sessions are keyed by minus the grant id** (`sessions`, `/pty/-n`, `sessions/-n/`). A brainstorm has no ticket, so no `runs` row (`ticket_id` NOT NULL); a migration rebuilding `runs` for one nullable column was not worth it. The janitor's existing checks work unchanged with negative keys.
- **Drag uses pointer events, not HTML5 DnD**: same behaviour, works with touch, and a real drag can be driven over CDP in the test.
- **Reset to Backlog is two operator calls** (PATCH, then revoke the ticket's live grants), done by the UI. PATCH first, so the killed agent's exit finds the ticket in Backlog and flags nothing.
- **Esc, Ctrl+L, Ctrl+N do nothing while a terminal has focus**: those keys belong to the agent there (Esc interrupts Claude Code).
- **Terminals the board opens on its own open behind the focused window and close themselves ~2 s after a reported outcome** (`submit`/`pass`/`fail`). Without this a Launch all buried the Board under a stack of windows. Revoked or crashed sessions stay open, titled "(ended)".
- **Extra REST beyond the handoff list**, each needed by a window: `/sessions`, `/inbox`, `/tickets/:id/diff`, `POST /brain`, `/config/*`, `/trust`, `/voice*`, `/brainstorm`, `/tickets/housekeeping`. A **New ticket** button too (POST /tickets existed; everything the daemon can do is reachable).
- **CSP widened** to `script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'`. transformers.js's WASM preload cache (which imports the runtime from a `blob:` URL) is turned off (`env.useWasmCache = false`) instead of allowing `blob:` scripts.
- **The download dialog shows every file's hash**, not one: the model is seven files.
- **The shell window is 1280×720** (was 1024×720), the acceptance size. One line in `main.rs`.
- **Not done: answering WebView2's microphone permission prompt in the shell.** The daemon's port is random, so the origin changes each start and WebView2 may ask again. Fix belongs with the shell work (phase 7): `PermissionRequested` → allow `Microphone` for our own origin only.
- **Mic in a real WebView2 was not exercised end to end** (the permission prompt is native chrome the probe cannot click). Transcription in WebView2 was exercised with the same `transcribe()` the mic calls; the mic → field and mic → terminal paths were exercised in Edge with a fake capture device.

## Gotchas for the next phase

- **Do not redirect `USERPROFILE` for the Tauri shell**: WebView2 then fails to start (silently, or with `0x800700AA` "resource in use" if an earlier WebView2 for `dev.kanban95.shell` is still alive). Killing the shell with `kill()` leaves `msedgewebview2.exe` children behind; kill the process tree, then check for `msedgewebview2.exe` with `kanban95` in its command line before the next start.
- The cargo cache in `shell/target` pointed at an old checkout path (`ai-taskboard`) and the build failed reading Tauri permission files; `cargo clean` fixed it (1m31s rebuild).
- WebView2 remote debugging for probes: `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333`, then `http://127.0.0.1:9333/json/list`. Phase 7 should make sure no such argument can reach a release build.
- Python on Windows writes CRLF in text mode; this repo is LF (`eol=lf`). Open files with `newline=''` when scripting edits.
- `/events` now carries `{ticket}` frames as well as sounds. Anything that listens on it must ignore frames it does not know.
- `runSettings` and `CLIS`/`EFFORT` live in `settings.ts` now; `lifecycle.ts` and `mcp.ts` import from there.
- Headless Edge resizes its window to `--window-size` minus chrome; `cdp.ts` sets the viewport with `Emulation.setDeviceMetricsOverride` to get exactly 1280×720.
- Phase 7's CSP work: the header in `server.ts` (`CSP`) is the one that governs the window; keep `'wasm-unsafe-eval'` or the mic breaks, and keep `blob:` out.
