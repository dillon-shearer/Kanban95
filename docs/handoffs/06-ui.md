# Phase 6 — UI

Read `CLAUDE.md`, `PLAN.md`, `docs/handoffs/log/*`. Vanilla JS, 98.css and xterm.js vendored. No framework, no build step.

## Goal
A Win95 desktop inside the Tauri window. Everything the daemon can do is reachable in two clicks or fewer; the common path (Launch all) is one.

## Windows (MDI, draggable, minimizable to a taskbar)
- **Board**: four columns; cards show id, title, model, effort, cli, flags as small badges, retry count. Model and effort are editable from the card's context menu without opening the ticket. Drag between columns is allowed only for operator-legal moves (backlog ↔ in_progress for manual override, anything → backlog to reset); illegal drops snap back. Launch, Launch all, New brainstorm buttons.
- **Ticket**: body + criteria, notes timeline (plan/decision/failure/summary/question/answer), git diff, runs with outcome, the rendered prompt for each run, grants for this ticket with Revoke.
- **Terminal**: one per run, xterm.js on the `/pty/<run-id>` websocket, title `#id — phase — model`.
- **Brain**: search box over FTS, results list, add note.
- **Settings**: models and effort per phase per CLI (reads and writes `~/.kanban95/models.json`), CLI paths, sounds on/off, Grants tab listing every live grant with Revoke, Voice tab (model download status, backend selector with only "local" at launch, push-to-talk vs toggle).
- **Inbox**: open `ask_operator` questions with an answer field; answering clears the flag.
- **Housekeeping** button on the Board toolbar: creates and launches a housekeeping ticket.

## Voice input
- `ui/voice.js`: a mic button component placed next to every text input and in every terminal window's title bar. Push-to-talk by default, toggle in Settings. Records with `MediaRecorder`, calls `transcribe(blob)`, inserts the text at the caret of the focused field or writes it to the pty as input (no trailing newline; the operator presses Enter).
- `transcribe` is one function with a `backend` switch read from Settings. The only backend at launch is local: transformers.js (vendored in `ui/vendor/transformers/`, no CDN) running a Whisper-class model with WebGPU when available, WASM otherwise. Confirm WebGPU/WASM availability inside Tauri's WebView2 on Windows during this phase and record the result in the log.
- The model file is not in the repo. First click on the mic opens a Win95 dialog showing the model name, source URL, size and SHA-256; on OK the daemon downloads it to `~/.kanban95/models/`, verifies the hash, and serves it to the UI from localhost. This is the only network call the board ever makes and it is operator-initiated.
- Visible state on the button: idle, recording, transcribing, error. Microphone permission denied shows a dialog explaining how to enable it, not a silent failure.
- Document Win+H as the zero-code fallback in `docs/OPERATOR.md`.

## Deliverables
- `ui/wm.js`: window manager (create, focus, drag by title bar, minimize to taskbar, remember positions in `localStorage`). Keep it under about 150 lines.
- `ui/app.js`: data layer over REST + the `/events` websocket; re-renders only the affected window.
- Taskbar with a Start-style menu for opening windows, clock, running-agent count.
- Keyboard: Esc closes the focused window, Ctrl+L = Launch all, Ctrl+N = New brainstorm.
- `docs/OPERATOR.md`: a short illustrated walkthrough of a full cycle.
- Log entry `docs/handoffs/log/06-ui.md`.

## Acceptance criteria
1. Brainstorm → tickets appear → Launch all → terminals open → tickets move on their own → ding. No page reload at any point.
2. An illegal drag snaps back with a status-bar message naming the allowed targets.
3. Revoke from Settings visibly kills the terminal window's session within one second.
4. Works at 1280×720 without horizontal scroll.
5. With the network disabled and the model already downloaded, the mic button transcribes a spoken sentence into the Inbox answer field and into a terminal.
6. With no model downloaded, the mic button leads to the download dialog and nothing is fetched before OK.

## Required tests
Use the `capture-ui` skill or a headless Chrome script against the running daemon:
- Illegal drop snaps back.
- Inbox answer clears the `needs_human` badge on the card.
- Window positions survive reload.
- `transcribe` with a bundled short WAV fixture returns the expected words (local backend, hash-verified model present).
- Model download with a wrong hash is rejected and the file deleted.
Everything else is verified by the phase 8 dogfood cycle, not by DOM unit tests.
